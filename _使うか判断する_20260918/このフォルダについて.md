# 使うか判断する（2026-09-18に移動）

`src/` から移してきた、**今のアプリが読み込んでいないファイル**です。
消してよいか決めきれていないので、いったんここに置いています。**まだ消していません。**

## 何のファイルか

Firebaseに移す前の、自前サーバー（Express）で動かしていた頃の残りです。

| ファイル | 元の場所 | 役割 |
|---|---|---|
| `index.ts` | `src/index.ts` | Expressサーバーの起動口 |
| `event.ts` | `src/routes/event.ts` | イベントのAPI |
| `friend.ts` | `src/routes/friend.ts` | フレンドのAPI |
| `auth.ts` | `src/middleware/auth.ts` | そのサーバーでのログイン確認 |
| `api.ts` | `src/services/api.ts` | 上のサーバーを呼びに行く通信部品 |

## 移した時点で分かっていること

- `index.ts` が `event.ts` `friend.ts` を読み込み、その2つが `auth.ts` を読み込む。
  **この輪の外から呼んでいる場所が無い。**
- `api.ts` は `MyPageView.vue` から `/api/users/sync` を呼ぶのに使われていたが、
  2026-09-18（#280）でその呼び出しを外したため、呼び出し元が無くなった。
  本番は Firebase Hosting で `/api` が存在せず、書き換え設定で index.html が返るだけだった。
- 移動後に `npm run build` と `npm test` が通ることを確認した。

## 消す前に確かめること（展示後に行う）

1. `event.ts` `friend.ts` が持っていた処理が、**今は Firebase 側のどこに当たるか**を1つずつ対応づける
   （イベント作成・参加・フレンド申請・承認）。対応先が無い処理が残っていないかを見る。
2. `auth.ts` の確認内容が、いまの `firestore.rules` と Cloud Functions の確認で
   同じかそれ以上になっているかを見る。
3. `api.ts` を使う予定が本当に無いか（外部APIを足す計画が無いか）を本人に確認する。
4. 上の3つが済んでから削除する。削除は本人の合意を得てから。

## 戻し方

`git mv` で移したので、履歴は切れていません。戻すときは元の場所へ `git mv` で戻します。
