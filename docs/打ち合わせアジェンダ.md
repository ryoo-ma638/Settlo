## 進行（時間配分）

### 1. 現状共有・何を直したか（3分）
- 「動くものはできた」→ **アプリをライブデモ**：
  - 未払い → 「支払った（承認リクエスト）」→ 相手の承認待ち
  - お知らせベル → 受け取った催促 → 「支払う」
  - 入金待ち → 「催促する」→「催促 N回」表示・再送は確認
- 直した要点（戦略doc §4）：鍵漏えい対応／UI全面リデザイン／実データ化／**1件の不正データで一覧が全部落ちるバグの発見と修正**

### 2. 振り返り：いけなかった点（5分）　← 戦略doc §1 の表
- 鍵を公開リポにコミット（履歴書き換えで対応済）
- **1人実装＋AIになっていた**（＝チーム開発になっていなかった）
- 配色バラバラ・モックのまま“動いて見える”・テストルール期限切れで全停止

### 3.【要・合意】体制の再設計（5分）　← 戦略doc §1-3
- **非コーダーにも「無いと開発が止まる成果物」を渡す**（デザイン仕様・ユーザー検証・テストシナリオ・デモ台本・スライド）
- リード3役を決める：**テックリード / デザインリード / PM・プレゼンリード**
- → その場で役割をホワイトボードに割り振る

### 4. 今後の方針（5分）
- **Geek Hack 狙うか？**（狙うなら §2 の改善：プレゼン・動画・デザイン）
- **差別化**（§3）：PayPayは“送金”、Settloは“記録・承認・催促・最小精算”レイヤー
- **アプリ化**（§5）：まず **PWA（半日・無料・インストール可）** → 必要なら Capacitor でストア化
